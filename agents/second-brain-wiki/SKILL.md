# Second Brain LLM 위키

이 스킬은 `second-brain` MCP 서버의 도구로 함께 쓰는 보관함을 읽고 씁니다.
보관함마다 규칙이 다를 수 있으니 **항상 `wiki_guide`를 먼저 호출해 그 규칙을 따릅니다.**
이 문서와 보관함 규칙이 다르면 보관함 규칙이 우선입니다.

## 공통
1. `wiki_guide` → 규칙, 폴더 구조, 내 권한 확인
2. `read_note("index")`로 지금 위키의 목차를 파악
3. 고치기 전에는 `read_note`로 `version`을 확인하고, `write_note`에 `expected_version`을 넘깁니다.
   "그사이 노트가 바뀌었습니다" 오류가 나면 다시 읽고 두 내용을 합친 뒤 다시 씁니다.
4. 사람이 쓴 문장은 지우지 않습니다. 덧붙이거나 다듬습니다.
5. 끝나면 `log` 노트 맨 위에 한 줄 기록을 남깁니다.

## 자료 넣기 (ingest)
사용자가 글을 붙여넣거나, 웹 주소나 PDF를 주며 "위키에 넣어줘"라고 할 때:
1. 자료를 직접 읽습니다. 웹은 가져오고 PDF는 엽니다.
2. `write_note(title: "YYYY-MM-DD 자료 제목", folder: "원본", mode: "create")`로 원문 또는 충실한 요약을 저장합니다.
   맨 위에 출처와 넣은 날짜를 적습니다.
3. 핵심 사실·주장·사람·회사·개념을 뽑습니다.
4. 각 항목마다 `search_notes`로 기존 위키 페이지를 찾습니다.
   - 있으면 `read_note` → 내용을 보태고 → `write_note(mode: "overwrite", expected_version)`
   - 없으면 `write_note(folder: "위키", mode: "create")`로 새 페이지를 만듭니다.
   - 사실마다 `[[원본 노트 제목]]` 출처를 답니다. 관련 페이지끼리 `[[링크]]`로 잇습니다.
   - 기존 내용과 부딪히면 `> [!warning] 상충하는 정보` 콜아웃으로 둘 다 남깁니다.
5. `index`에 새 페이지를 분류별로 추가하고 `log`에 기록합니다.
6. 사용자에게 무엇을 만들고 고쳤는지 짧게 보고합니다.

## 질문 (query)
1. `index`와 `search_notes`로 관련 페이지를 찾고 `read_note`로 읽습니다. 필요하면 원본까지 읽습니다.
2. 근거가 된 `[[페이지]]`를 밝히며 답합니다. 위키에 없으면 없다고 말합니다.
3. 다시 쓸 가치가 있는 답이면 위키 페이지로 저장할지 묻습니다.

## 점검 (lint)
1. `find_problems`로 끊긴 링크, 고아 노트, 빈 노트를 찾습니다.
2. 위키 페이지를 훑어 모순, 출처 없는 주장, 오래된 정보, 새 페이지로 만들 만한 주제를 찾습니다.
3. `위키/점검 보고 YYYY-MM-DD`로 보고서를 쓰고, 확실한 것은 바로 고칩니다.

## 최근 변경 반영
사람이 앱에서 새로 쓴 메모를 위키에 반영해 달라고 하면
`recent_changes`로 바뀐 노트를 찾고, 위 "자료 넣기" 4~6단계를 적용합니다.
